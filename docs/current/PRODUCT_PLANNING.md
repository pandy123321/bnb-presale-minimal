## 产品概述

BingGoPlus 是一个链上代币交易、持有者分红与治理产品。用户用 BNB 买卖链上名称和符号均为 `PANGU2` 的代币，系统通过 PancakeSwap V2 提供流动性。

品牌与链上标识必须分开：产品品牌使用 **BingGoPlus**；已部署合约、ABI、事件和 Token 元数据继续使用 `Pangu2* / PANGU2`。产品文案不得为链上 Token 虚构其他 symbol。核心设计理念：

- **透明税收** — 买卖税率公开可见，不可篡改
- **社区分红** — 前 100 名持有人定期分钱
- **托底回购** — 卖出税进入托底池，在合约条件满足时可触发回购
- **自主锁仓** — 用户可选任意期限锁仓赚利息

## 三、合约经济模型

### 3.1 税收规则

| 场景 | 税率 | 钱去哪了 |
|------|:--:|------|
| 平时买入 PANGU2 | **4%** | 进分红池，分给前 100 名 |
| 平时卖出（没赚钱） | **4%** | 进托底池，为回购提供资金 |
| 平时卖出（赚钱了） | **10%** | 9% 进托底池 + 1% 永久销毁 |
| 🛡️ 开盘 15 分钟内买入 | **30%** | 进分红池 |
| 🛡️ 开盘 15 分钟内卖出 | **30%** | 29% 托底 + 1% 销毁 |
| ⭐ 白名单买入 | **0%** | 免收税 |
| ⭐ 白名单卖出 | **0%** | 免收税 |

### 3.2 怎么判断"赚钱了"

系统会按卖出数量取对应比例的历史 WBNB 成本，并用合约 TWAP 预估当前卖出价值：

- 成本状态为 `KNOWN`，且当前 TWAP 卖出价值 ≤ 对应历史成本 → 收 4%；
- 成本状态为 `KNOWN`，且当前 TWAP 卖出价值 > 对应历史成本 → 收 10%；
- 成本为 `UNKNOWN`、卖出数量超过可证明余额或无法完整证明成本 → 按 10% 处理（fail closed）。

### 3.3 分红规则

持有 PANGU2 最多的 **前 100 名**地址按比例分红：

| 排名 | 分红比例 |
|------|:--:|
| 第 1~10 名 | 35% |
| 第 11~30 名 | 25% |
| 第 31~60 名 | 25% |
| 第 61~100 名 | 15% |

**分红流程**：管理员充钱 → 系统快照锁定前 100 名 → 发布名单 → 前 100 名来领取（30 天内）

### 3.4 回购机制

- 单次成功回购固定使用 **0.01 BNB**；距上一次成功回购必须至少 **60 秒**；
- 60 秒是最小冷却时间，不是定时器，也不承诺每 60 秒一定发生回购；
- SupportPool 余额、Locker、Oracle、报价、最小输出和滑点等合约条件必须同时满足；
- 买回来的 PANGU2 进入 Locker 并锁仓 **365 天**；
- **任何地址都可以触发回购**（不限于管理员），触发者不会收到回购资产。

### 3.5 锁仓收益

| 规则 | 说明 |
|------|------|
| 最低锁仓 | 1 PANGU2 |
| 最长锁仓 | 730 天（2 年） |
| 可选期限 | 30 / 90 / 180 / 365 天 |
| 提前解锁 | 扣 10% 罚金 + 没收全部利息 |
| 奖励来源 | 管理员手动充值 |
| 奖励速率上限 | 已部署合约限制全局每秒奖励速率；不是每名用户固定约 10 PANGU2/天，实际收益取决于质押占比、时长和奖励储备 |

### 3.6 开盘保护

| 阶段 | 时长 | 说明 |
|------|------|------|
| 等待期 | 部署后 ~ 约 1 小时 | 合约部署 → 初始流动性注入 → 等 30 分钟价格稳定 → 验证通过 |
| 保护期 | 开盘后 15 分钟 | 买卖税 30%，防止抢跑脚本 / 夹子 |
| 正常期 | 15 分钟后 | 进入正常税收模式 |
